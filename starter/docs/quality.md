# Quality and dependency policy

`scripts/check.sh` is shared by local development and CI: formatting, Clippy with warnings denied, unit/HTTP/PostgreSQL tests, generated OpenAPI drift, cargo-deny, and locked release build. `scripts/container-smoke.sh` builds the Dockerfile, starts its own isolated PostgreSQL/network, applies migrations twice, verifies readiness and both example settings, checks note persistence and log redaction, runs with read-only filesystem/dropped capabilities, and checks a clean SIGTERM exit. Docker resources created by that script are cleaned on exit. No production credentials are needed.

Supported configuration matrix: Rust 1.98.1, Linux x86_64, PostgreSQL 18.6, example routes disabled and enabled, and AUTH_MODE off/bearer. HTTP tests and container smoke cover the shipped anonymous teaching mode and configured bearer verification. Tests also exercise configured/default CORS, rate limits and concurrency rejection/recovery. OpenSSL CLI signs public test-only tokens in the container smoke; keys stay outside the runtime image. Optional starter features are mail, storage, cache, outbound and telemetry. Framework checks test all enabled adapters and compile each integration feature independently plus the core without optional features; generator smoke compiles and tests a complete generated application. ARM and native Windows are not claimed as verified.

Install cargo-deny 0.20.2 with `cargo install cargo-deny --version 0.20.2 --locked`. `deny.toml` enforces license and source allowlists, denies yanked dependencies, and checks RustSec advisories; duplicate versions are warnings because upstream libraries can legitimately use distinct major versions. Investigate each advisory; prefer an upgrade. Any exception needs a documented scope, justification, owner, and expiry. Offline advisory checks are not fresh security evidence.

For dependency changes: read upstream release notes, modify `Cargo.toml`, update only the intended packages, review `Cargo.lock` and `cargo tree -e features`, and run both scripts. Keep optional integration dependencies in recipes until implemented. Review the toolchain, Docker builder tag, Rust version field, and CI together when upgrading Rust. Pin deployed image digests in the adopting project's release process and regularly rebuild for OS updates; repository tags deliberately remain readable and patch-updatable.

Generate OpenAPI with `bash scripts/openapi.sh write`. Commit the actual generated diff; drift checks do not rewrite it. A behavior change requires relevant failure-path coverage, whereas documentation-only changes need link/path checks rather than artificial failing tests.

Hosting setup (instructions, **not enabled here**): protect the default branch with PRs, one independent approval, stale approvals dismissed after new commits, and passing `CI / core` and `CI / container` checks (select the actual check contexts emitted by the host). Block force pushes/deletion, require resolved conversations, and restrict workflow changes to reviewers with repository access. Use read-only workflow permissions; pull-request checks have no deployment secrets and do not use `pull_request_target`. Configure dependency updates and review Docker/action/tool versions regularly. No remote repository or branch rules were configured by this implementation.
